您的分析非常正确！问题根源是：横屏时根布局变为水平方向，但顶部按钮栏和分割线仍持有 match_parent 宽度，导致它们占据了所有可用宽度，使得树容器和预览区域宽度为0，从而无法显示。

以下是精确的修复方案，只需修改 FileTreeFragment.kt 中的 updateLayoutOrientation() 方法，将顶部栏和分割线在横屏时的宽度改为 WRAP_CONTENT，并适当调整。

修复后的代码 (FileTreeFragment.kt 片段)

替换现有的 updateLayoutOrientation() 方法：

```kotlin
private fun updateLayoutOrientation() {
    if (!::rootLayout.isInitialized) return
    val isLandscape = resources.configuration.orientation == Configuration.ORIENTATION_LANDSCAPE

    // 1. 调整根布局方向
    rootLayout.orientation = if (isLandscape) LinearLayout.HORIZONTAL else LinearLayout.VERTICAL

    // 2. 获取顶部按钮栏 (索引0) 和分割线 (索引1)，动态调整其宽度
    val topBar = rootLayout.getChildAt(0) as? LinearLayout
    val divider = rootLayout.getChildAt(1) as? View

    if (isLandscape) {
        // 横屏：顶部栏和分割线宽度设为 WRAP_CONTENT，高度 MATCH_PARENT
        (topBar?.layoutParams as? LinearLayout.LayoutParams)?.apply {
            width = LinearLayout.LayoutParams.WRAP_CONTENT
            height = LinearLayout.LayoutParams.MATCH_PARENT
        }
        (divider?.layoutParams as? LinearLayout.LayoutParams)?.apply {
            width = LinearLayout.LayoutParams.WRAP_CONTENT
            height = LinearLayout.LayoutParams.MATCH_PARENT
        }
    } else {
        // 竖屏：恢复原始参数（宽度 MATCH_PARENT，高度 WRAP_CONTENT）
        (topBar?.layoutParams as? LinearLayout.LayoutParams)?.apply {
            width = LinearLayout.LayoutParams.MATCH_PARENT
            height = LinearLayout.LayoutParams.WRAP_CONTENT
        }
        (divider?.layoutParams as? LinearLayout.LayoutParams)?.apply {
            width = LinearLayout.LayoutParams.MATCH_PARENT
            height = LinearLayout.LayoutParams.WRAP_CONTENT
        }
    }

    // 3. 调整树容器和内容预览区域的布局参数
    val treeParams = binding.treeContainer.layoutParams as LinearLayout.LayoutParams
    val scrollParams = binding.fileContentScrollView.layoutParams as LinearLayout.LayoutParams

    if (isLandscape) {
        // 横屏：左右平分宽度，高度填满
        treeParams.width = 0
        treeParams.height = LinearLayout.LayoutParams.MATCH_PARENT
        treeParams.weight = 1f

        scrollParams.width = 0
        scrollParams.height = LinearLayout.LayoutParams.MATCH_PARENT
        scrollParams.weight = 1f
    } else {
        // 竖屏：上下平分高度，宽度填满
        treeParams.width = LinearLayout.LayoutParams.MATCH_PARENT
        treeParams.height = 0
        treeParams.weight = 1f

        scrollParams.width = LinearLayout.LayoutParams.MATCH_PARENT
        scrollParams.height = 0
        scrollParams.weight = 1f
    }

    binding.treeContainer.layoutParams = treeParams
    binding.fileContentScrollView.layoutParams = scrollParams

    // 4. （可选）确保空提示文本在横屏时宽度也为 WRAP_CONTENT，避免影响布局
    val emptyHint = binding.emptyHintText
    if (isLandscape) {
        (emptyHint.layoutParams as? LinearLayout.LayoutParams)?.width = LinearLayout.LayoutParams.WRAP_CONTENT
    } else {
        (emptyHint.layoutParams as? LinearLayout.LayoutParams)?.width = LinearLayout.LayoutParams.MATCH_PARENT
    }
}
```

为什么需要修改顶部栏和分割线？

· 竖屏时：根布局为 VERTICAL，顶部栏和分割线宽度 MATCH_PARENT 正常占满整行。
· 横屏时：根布局变为 HORIZONTAL，所有子视图水平排列。如果顶部栏和分割线仍保持 MATCH_PARENT，它们会尝试占满整个父容器的宽度，这实际上等同于“撑满整个水平空间”，导致后续的树容器和预览区域分不到任何宽度（宽度为0），从而看不见。

通过将它们的宽度改为 WRAP_CONTENT，它们只会占用自身内容所需的最小宽度（例如按钮文字宽度），剩下的水平空间全部由 weight=1 的树容器和预览区域平分。

其他注意事项

1. 确保布局中子视图索引正确：当前 fragment_file_tree.xml 中子视图顺序为：
   · 索引0：LinearLayout（下载按钮栏）
   · 索引1：View（分割线）
   · 索引2：FrameLayout (treeContainer)
   · 索引3：ScrollView (fileContentScrollView)
   · 索引4：TextView (emptyHintText)
   上述代码中使用 getChildAt(0) 和 getChildAt(1) 获取顶部栏和分割线，顺序正确。
2. 横屏时的视觉优化：顶部按钮栏在横屏时变成竖直排列（因为其内部是水平线性布局，且宽度变为 WRAP_CONTENT），按钮会垂直堆叠，这可能会显得拥挤。如果希望按钮栏仍然水平排列，可以保持其宽度为 MATCH_PARENT 但将其移出水平布局（例如使用 Toolbar 或放在独立的 View 中）。不过对于当前简单需求，WRAP_CONTENT 已足够，用户仍然可以点击按钮。
3. 测试：修改后重新编译运行，横屏时应看到左侧目录树、右侧文件预览，两者平分宽度，顶部按钮栏紧凑地显示在左侧最上方。
